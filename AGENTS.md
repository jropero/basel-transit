# AGENTS.md

Basel tram/bus departures and route planner. React 19 + TypeScript on Vite+ (`vp`), installable PWA, Windows Phone "Metro" look. Data comes from the Swiss OJP 2.0 API (XML). For setup and deployment, see [README.md](README.md).

## Commands

- `vp dev`: dev server at http://localhost:5173/b/ (base is `/b/`)
- `vp run build`: `tsc` type check + production build. Run it after every change; there is no test runner.
- `vp lint` (`pnpm lint`): Oxlint with type-aware checks plus SonarJS rules (cognitive complexity max 6, no nested ternaries). Rules live in the `lint` block of `vite.config.ts`; SonarJS loads via `lint/sonarjs.js`. Fix findings rather than disabling rules; if a rule really doesn't fit, turn it off in the config with a one-line reason, not inline.
- `vp fmt` / `vp fmt --check` (`pnpm format` / `pnpm format:check`): Oxfmt, single quotes, 96 columns (`fmt` block in `vite.config.ts`)
- `pnpm lint:css`: stylelint on `src/index.css` (`.stylelintrc.json`, standard config)
- `pnpm typecheck`: `tsc --noEmit`. `vp check` runs format, lint and type checks together.
- Pre-commit hook (`.husky/pre-commit`, installed by `pnpm install` via `prepare`) runs `vp staged`: lint/format staged TS files, stylelint staged CSS. Needs Node >= 22.22 (`.node-version` pins 26.12.1).
- Package manager: pnpm (`vp add`, `vp remove`)

## Layout

- `src/ojp.ts`: everything shared. Request builders (`envelope`, `searchBody`, `nearBody`, `tripBody`), `ojp()` fetch, XML helpers (`text`, `all`), parsers (`parseStops`, `parseTrips`), localStorage helpers (`loadJson` / `saveJson`, `loadStops`, `loadRoutes`), formatting (`hhmm`, `short`). Also `ojpCached` (last-known XML for offline), situations and flags parsing, the known-stops directory and headways. Put new shared logic here.
- `src/App.tsx`: departures view. Saved-stop pivot, search, near me, groups by line + `DirectionRef`, onward stops (prefetched, cached 7 days), alerts, 15s auto-refresh. `App` holds the saved stops (`updateStops`) and passes them to `Settings`, whose `SavedOrder` reorders them with ↑/↓ buttons (`moveSaved` in `src/ojp.ts`); the pivot follows that order (saved routes are not reorderable). A by line / by time switch (`SortSwitch`, `basel-transit:sort` = `'line' | 'time'`, `parseSort`) sits above the list: by time = `TimeRows`, one single-departure `LineGroup` per departure in expected-time order, all lines mixed, capped at `TIME_ROWS_MAX` 30 (`timeOrdered`); onward stops only open by line. A departures / arrivals switch (`BoardSwitch`, kept while browsing stops, not across reloads) sits above it: arrivals = `StopEventType` arrival, `parseDepartures(doc, true)` reads `ServiceArrival` of `ThisCall`, rows are labelled "from <origin>" and grouped by line + `OriginText` (`fromLabel`); cached under `arrs:<ref>`, no onward prefetch.
- `src/Follow.tsx`: follow a vehicle (every mode, departures and arrivals). In an open line group `OpenGroup` (`App.tsx`) shows `TripPicker` (one `aria-pressed` button per departure, first by default) and `FollowTrip`: `OJPTripInfoRequest` (`tripInfoBody`, `parseTripInfo` in `src/ojp.ts`; `JourneyRef` + `OperatingDayRef` come from the `StopEvent`) gives every call (PreviousCall + OnwardCall by `Order`, no CurrentPosition), refreshed every 15 s while the pane is active and the page visible (`useTripInfo`). Earlier stops fold behind "N earlier stops", `tripProgress` derives the position row from estimated (else timetabled) times (at / arriving in the last minute / between), passed stops are dimmed, late stamps (`lateMinutes` >= 1) use `--late`; stop names are "Town, Stop": lists show only the stop part (`splitTown`) and a muted uppercase `TownRow` heading at the first row and wherever the town changes (`townHeadings`, in the follow view and the cached onward list; `short()` stays for titles and chips); status `live · HH:MM` / `no live data` / `offline`. When the journey can't be fetched the cached onward stops (`OnwardStops`) show instead. An error answer is HTTP 200 with `ErrorCondition` and no `TripInfoResult`.
- `src/nav.ts` (`useStopNav`): stop navigation history. Every stop of an open group's list (follow view or cached onward list; `StopLink` in `Follow.tsx`, "Show departures for <name>", not the stop being shown) jumps there: the stop is selected (not saved), the pane scrolls to top and a history entry `{view:'departures', stop, trail, openLine}` is pushed (the entry left is replaced with its `openLine`, so system back re-expands the line). Stop refs come from the call's `StopPointRef` minus the quay suffix (`placeRef`; cached onward stops carry `ref`, key `onward3`). `trail` (stops from the exploration start to here, restored from `history.state` on reload) drives the breadcrumb row (`Trail.tsx`, earlier crumbs call `history.go(-n)`); picking a saved stop only `replaceState`s and clears it. The pivot's `{pivot:true}` entry sits on top of the app entry: `write` and `jump` never touch it, and its popstate handler (`usePivot`) and `useStopNav`'s coexist because pivot entries carry no `stop`.
- `src/Route.tsx`: route view (`OJPTripRequest`). From/to, saved routes, 15s auto-refresh.
- `src/RefreshBar.tsx`: Metro countdown bar and loading dots. `src/Alerts.tsx`: alert banner and ⚠ mark. `src/Access.tsx`: ♿, replacement, quay-change and diverted marks.
- `src/AppBar.tsx`: bottom app bar (round Fluent icons, ••• menu). `src/Settings.tsx` + `src/accent.ts`: accent colour picker (20 Windows Phone accents, `--accent` / `--on-accent`). `src/motion.ts`: tilt on press. `src/icons.tsx`: vendored Fluent UI System Icons (MIT, see `src/icons.LICENSE.txt`); don't add the icon package as a dependency.
- Views are a swipe pivot (departures | route | settings) in `App.tsx` (`usePivot`, `PivotHeader`): the headers loop, and system back returns to departures.
- Weather (stop title): `WeatherMark` (`src/Weather.tsx`, far right of `.title-row`, the flex row around the title `h2`, vertically centred on a wrapped title; its right edge lines up with the minutes column `.dep .left`) shows a Fluent icon + rounded temperature (`.weather`, `role="img"`, English `aria-label` e.g. "Overcast, 14 °C"). Coordinates: the selected stop's `lat`/`lon`, else `knownCoords(ref)` (known-stops directory, filled by `rememberDoc` from the departures response, so a saved stop without coordinates gets weather after its first load); none: no element, no fallback. Source: Open-Meteo `v1/forecast?current=temperature_2m,weather_code,is_day&timezone=Europe/Zurich` (no key, CORS, client-side, CC BY 4.0 credited in Settings and README). `fetchWeather` (`src/ojp.ts`) takes the coordinate rounded to 2 decimals (`weatherKey`, ~1 km: the exact stop is not sent), memoises 15 min, keeps the last answer per coordinate in `basel-transit:cache:weather:<lat,lon>` (evictable by `saveJson`, dropped past 3 h), 8 s timeout, never throws or retries (failure: stored copy or nothing, not memoised). It runs when the rounded coordinate changes and when the page becomes visible; no polling. Pure mapping (WMO code + `is_day` to icon and label, `formatTemp`, `parseWeather`, self-checks) is in `src/weather.ts`. `sw.js` ignores cross-origin requests, so Open-Meteo is never cached there.
- `public/sw.js`: service worker for the offline app shell (production only). `public/fonts/`: Selawik (OFL) as the Segoe UI fallback.
- `src/index.css`: the only stylesheet, plain CSS with tokens on `:root`. Theme auto / light / dark (`src/theme.ts`, `basel-transit:theme`, `data-theme` absent = auto; light overrides on `:root[data-theme='light']` and in `prefers-color-scheme: light`; `index.html` sets it before first paint). No CSS framework: don't add one.
- `public/`: PWA manifest and icons. Paths are absolute `/b/...`.

## OJP API notes

- Every request is a POST of an XML body built with `envelope()`. Escape user input with `escapeXml`.
- **Dev:** `ojp()` posts to `/ojp`, and the Vite proxy adds `Authorization: Bearer $OJP_TOKEN`. The proxy path is `/ojp`, **not** `/b/ojp`.
- **Production:** `ojp()` calls the API directly, with the token inlined at build time (see README).
- Parse with `text(el, localName)` / `all(el, localName)`. They're namespace-agnostic (`siri:` vs default namespace) and return the **first** descendant, so scope to the right element. In a `StopEvent`, `ThisCall` comes before `OnwardCall`.
- Times are UTC ISO strings. Display them with `hhmm()` (de-CH).
- Stop IDs are SLOIDs, e.g. Burgfelderplatz `ch:1:sloid:89303`. `ch:1:sloid:10` is the Basel SBB _train_ station, not the tram stop; the tram stop "Basel, Bahnhof SBB" is `ch:1:sloid:78143`.
- English alert text comes from `siri:ServiceRequestContext/siri:Language` as the first child of `siri:ServiceRequest` (set by `envelope()` via `LANG`). `Params/Language` has no effect. Alerts (`PtSituation`) sit in the response context; `Service/SituationFullRefs/SituationFullRef/SituationNumber` in each `StopEvent` / `TimedLeg` points at them. `Cancelled` and `Deviation` sit in `Service`; `EstimatedQuay` next to `PlannedQuay` in the call.
- **Before relying on a response shape, check it live:** with the dev server running, `curl -X POST localhost:5173/ojp -H 'Content-Type: application/xml' --data-binary '<OJP …>'`.

## Rules

- Never read, print or commit `.env`; it holds `OJP_TOKEN`.
- Wrap localStorage access in try/catch (use `loadJson` / `saveJson`). Keys are prefixed `basel-transit:`.
- Keep it small: no new dependencies for things a few lines can do. New parsing or maths logic gets an inline `console.assert` self-check (see `isoMinutes`, `metres`).
- Interactive elements are real `<button>`s with `aria-*` state. Don't put `<div>`s inside buttons; use `<span>`.
